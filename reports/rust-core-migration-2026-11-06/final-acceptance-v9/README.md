# FrameKernel 双端完整回归

Android 真机与 iOS 模拟器使用同一批 8 份冻结素材，各完成 62 项。两端都使用本轮的编译源码，实际走完旧流程、原尺寸 4K 和专项矩阵，并通过独立媒体审计与隐私复核。最终这一轮在指定素材和环境中没有发现新的未解决问题。

编译源码：`14f95fe1cedcf638e9c59855a378bcd83623aa76`。可公开的[验收汇总](acceptance-summary.json) SHA-256：`4fb676a6fcdf46cbf0474c9ba4a00cbd79eed184aa0da9233d2e13d537d9ab3c`。两端的原始结果和人工复核素材保留在各自主机。

## 共享范围与修复

FrameKernel 是独立的 MIT Rust 库（crate `frame-kernel`，C ABI `frame_kernel_*`）。两端共用坐标、模型前后处理、跟踪和隐私选择、当前人脸归属、时序保护、跟随裁剪与导出状态转换。平台保留推理执行、像素缓冲、GPU 渲染、编解码及系统相册操作。核对了已实际安装的两份模型，Android 和 iOS 的模型字节一致。

多人邻人归属结合当前遮挡区域和几何判定；顶部截断、侧脸和贴近裁剪边缘的人脸按当前可见区域保守覆盖。此前全长 4K 回归还定位到尾部一个无归属人脸未用共享采样余量，已统一应用同一余量。修复未延长身份保护期限或修改豁免规则。可单独查看[全长尾帧的诊断与修复验证](../standalone-face-coverage/README.md)。

## 构建与限制

Windows 和 Mac 均使用 Rust 1.97.1，修订 `8bab26f4f68e0e26f0bb7960be334d5b520ea452`。两端 Rust fmt、Clippy、96 项测试通过；Android JVM 621 项（151 个套件），失败、错误和跳过为 0；Mac Swift 通过 512 个几何对照、跟踪及独立人脸采样余量检查。见[主机检查](host-checks.json)、[工具链](toolchain-activation.json)与[编译源码 CI](compiled-source-ci.json)。

本地复核和汇总见[工具说明](tools/README.md)。提交内容只含通用代码、合成测试及安全汇总。原始人脸观测、掩码、坐标、裁片、复核图及批准账本保留在各自主机。Android 为 OnePlus 8T KB2000 / API 34；iOS 为 iPhone 15 Pro / iOS 17.0.1 模拟器，不能证明 iPhone 硬件性能。重叠与身份不确定时仍可能保守多遮或出现重叠贴纸。原始音轨包含静音素材，本轮不能判断主观口型同步。
