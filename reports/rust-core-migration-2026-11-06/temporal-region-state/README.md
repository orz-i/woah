# 共享区域时序与导出清理阶段回归

本阶段代码基线为 `fec72da327fa4524c01ed7c50f51752ca6d83059`，核心库继续使用独立的 FrameKernel 命名。
Android 真机与 iOS 模拟器各完成 13 项专项流程，以及额外的 8 项疑难区间单帧裁剪。
这不是两端各 62 项最终验收；完整状态跟踪、统一脸模型和剩余导出协议仍在迁移。

## 修复范围

- Rust 统一面部区域的时序稳定、弱观测下的锚框位移、有限时间的实测区域保留与保守合并。
  连续区域只增加当前全场景保护，不建立身份归属，也不产生主角免遮。
- 全场景选择使用当前帧目标；个体、混合选择和主角仍保持原身份约束及歧义保护。
  iOS 原生预览补齐未归属身体框的人脸。
- Rust 为非零裁剪和预览规划前序素材时间点。两端原生负责精确解码和模型执行，
  将前序观测交给同一个区域状态；前序画面不进入输出帧和时间线。
- Rust 统一工作任务终态：取消请求先阻止提交，实际资源及临时文件清理完成后才公开终态；
  已提交的成功结果不被迟到的取消覆盖。iOS 取消后的排队重试继续串行执行。
- Android 原生 MP4 适配器为单视频帧和单个音频访问单元写入明确的末样本时长。
  平台编解码器、文件、线程、GPU 和系统相册仍由原生持有。
- QA 使用隔离 Android 包、Activity 自持亮屏、只读 ADB 短时重连、不可覆盖的运行 ID，
  并把实际预览、编译来源、视频和相册原片绑定到证据。

## 真实发现与复测

| 发现 | 修复与证据 |
| --- | --- |
| 首帧身份约束使非零时间的全场景预览失败 | 统一当前目标选择；保留初次 Android 6 项、iOS 7 项失败记录 |
| iOS 源帧 343 / 13720 ms 预览脸部露出 | 原生接入全场景未归属人脸保护；当前视频与实际预览均复核 |
| Android 抬臂源帧 559、560 连续导出露出人脸 | Rust 加入近时实测区域的保守空间连续；保留修复前像素证据 |
| 从源帧 559 直接开始裁剪或预览仍露出人脸 | 两端加入共享规划的前序素材观测；扩展检查源帧 556–563 的独立冷启动 |
| Android 单帧视频轨时长为 0、帧率为 1/0 | 明确末视频样本时长；当前 559 输出为 25/1、0.040000 秒、1 帧 |
| 极短裁剪只含一个 AAC 单元时解码为空 | 明确单音频单元末样本时长；当前 8 段均通过实际音频解码检查 |

| 手动重启同一运行会覆盖已有证据 | 新运行目录保护；两端实测重启后既有文件哈希不变、无重复导出轨迹 |

## 保留的限制与后续工作

- 抬臂弱观测会保守扩大脸部或贴纸范围，群体场景也可能产生多余区域。
  本阶段修复漏遮，不把扩大范围描述为定位精度改善。
- 本轮带音轨片段的参考 PCM 为静音；已检查音轨、实际解码、静音一致性及时间戳，
  `alignment_observable=false`，不据此声称验证了可听音频的同步精度。
- 晚时刻的个体 / 主角预览仍需要完整共享状态跟踪和历史重放，不能用放宽身份门限替代。
  统一脸模型与剩余隐私 / 导出协议也尚未全部迁移。
- 已启动相同 8 份冻结素材的当前版本完整 62 项基线回归，用于继续发现长时 4K 和遗留问题；
  它不是迁移完成后的最终验收。旧的中断、锁屏和已知失败运行均不计作通过。
- 模拟器结果不代表 iPhone 真机性能；额外检测带来的处理耗时需继续在长时回归中记录。
