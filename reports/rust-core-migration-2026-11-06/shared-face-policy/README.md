# 共享跟踪、人脸几何与归属阶段

FrameKernel 使用中性的库名、MIT 许可证和独立 Cargo 工程；当前仍为 `publish = false`。
Windows 与 Mac 均固定 Rust 1.97.1。同一输入下，身份会话、保护类别、几何与补脸规则只由 Rust 实现；原生层执行解码、模型推理、GPU 绘制、资源清理与系统相册操作。

本阶段移除了生产 Kotlin/Swift 中已迁移的跟踪、保护类别和人脸几何数值实现。原始 Native 副本只保留在测试目录，用于独立比对，不能替代真实输出验收。两端使用相同 SHA 的 YOLO 和 BlazeFace 模型，共享预处理和结果解码；不同解码器、推理后端及 GPU 仍可能产生不同观测或边缘像素，不要求编码文件字节相同。

已完成的证据包括：

- 960 帧原始跟踪状态语料、1024 步原始保护类别语料，以及 512 组几何、投影和归属规则比对；保留原有歧义、长遮挡、当前掩膜不足和错误输入的保守保护检查。
- 实际 Android 190 帧与 iOS 166 帧输入回放，修复强独立观测仍被历史遮挡组保留的问题。没有放宽未知人物、空掩膜或非唯一观测的豁免条件。
- 两端各 13 项专项流程与 8 项独立单帧冷启动裁剪。媒体、预览取帧时间、相册原件和取消后立即重试检查通过；每组另有 16 个实际不透明红色像素探针。13 项首中尾及全部原生预览已经人工复核；冷启动面部切片也已查看。
- Windows 74 项 Rust 单元、7 项冻结输入回放、1 项文档测试，612 项 JVM 和 105 项 Python 合约测试通过。各记录保留自己的实际源码阶段；完整最终安装包验收单独记录。

`android-stage`、`ios-stage` 保留未改写的原始审计结果及绑定源文件、输出和图片哈希的人工判断。Android 来源 343 帧和 iOS 来源 147/577 帧的检测宽框包含头发、耳侧、手臂或颈部；放大实际视频确认眼鼻口已覆盖。自动失败/待复核状态没有改写为自动通过。抬臂帧大范围兜底、尾部的小块保守多遮及 Unknown 保护仍保留为精度限制。

`hero295` 记录完整跟随回归中新发现的 11.8 秒主角误遮：渲染用关键点中心移动了归属采样窗，实际当前掩膜支持从原测量框的 12/16 降至 8/16。修复在共享 Rust 中使用测量框判断归属，保持至少 4 个独立像素、12/16 支持点和其他唯一归属条件。真实输入回放只改变第 14 个候选的归属，移除一个重复检测，其他 15 个候选不变；空当前掩膜仍不能豁免。修复后实际 331 帧片段的第 165/295 帧主角覆盖率为 0，其他可见人脸保持保护。共同测试器新增 11.8 秒原生预览点。

干净 CI 环境还补齐模型在 CocoaPods 解析前的固定字节部署，并在运行模拟器前验证最终应用包内的两个模型。该修复处理真实缺失资源，不降低运行验证要求。

**最终验收仍在运行。** `ce25a0d3` 两端安装包正在分别完整执行 22 + 27 + 13 项，不使用用例过滤。27 项原尺寸 4K 包含 15618 个计划输出帧，并在同一应用进程内验证处理至少 25 帧后的取消及立即重试。此前被中断的运行不计入最终通过数；上述阶段结果不能冒充两端各 62 项最终通过。静音音轨不能证明可听音画同步，iOS 模拟器结果也不代表 iPhone 硬件性能。
