# Woah 首页卡片化改造：设计与验收规范

> 状态：实施基线（2026-10-23）。范围仅限 Flutter Mobile 首页与工具发现层；不涉及检测、隐私保护算法、导出、分辨率或性能路径。

## 背景和证据

- 既有首页 `ImportVideoScreen` 使用独立深蓝星空配色、环绕星星图标和占据大面积的吉祥物动画；其复杂视觉层级影响主任务发现。
- 现有首页的「人脸贴纸」「智能裁切」「更多工具」卫星是 `_FeatureSatellite` 装饰组件，没有点击行为；不能把它们误标成已独立提供的功能。
- 真实可运行的独立入口只有「选择视频」：`pickAndProbeVideo()` → `createProject()` → `/protection_editor`，结束后 `reset()`。应原样保留。
- 人脸贴纸、跟随主角裁切、智能拉腿等是统一保护编辑器内的可选能力，不能假设它们目前拥有独立处理路由。
- 当前 `AppTheme` 使用黑色／石墨灰／暖金色，首页另立蓝黄主题。首页应回归同一套 `AppTheme` token，降低跨页面视觉断层。

## 决策

首页定位从「功能宣传画面」转为「快速进入当前工作流的工作台」。采用单主卡、次级工具入口和渐进式卡片扩展；不引入底部导航栏、不放置巨大双按钮、不在首页展示不可点击的假工具。

### 结构

1. **首页 `/`**：紧凑的 Woah 品牌行（保留长按进入原彩蛋）、一句简短辅助文案、单张真正可点击的「视频隐私保护」主卡；下方轻量「全部工具」导航。
2. **主卡**：整张卡片是单一触摸区域，文字「视频隐私保护」「选择视频」语义明确；不再叠放一个独立大按钮。允许非交互的抽象媒体视觉，避免强依赖示例用户视频与身份图像。
3. **工具库 `/tools`**：列出一个「立即开始」视频隐私保护任务，以及以独立说明区呈现的编辑器内能力（跟随裁切、人脸贴纸、人物特效）。前者可直接触发同一导入工作流，后者明确标注「导入视频后在编辑器内使用」，不得伪装为单独可运行的卡片。
4. **保护编辑器 `/protection_editor`**：不改现有流程、参数、保护或导出逻辑；从首页和工具库触发的视频导入必须走同一个共享操作入口。
5. **未来新增独立工具**：从类型化工具注册表提供内容、图标、状态及进入动作；当可独立运行的主工具多于一个时才启用横向卡片切换、露出下一张边缘和位置指示。不以占位卡凑轮播数量。

### 交互

- 主卡整卡点击（触摸目标大于 48dp）→ 原生视频选择 → 元数据探测 → 统一保护编辑器。导入期间防重复触发，保持屏幕内可见忙碌状态；取消选择仍停留在原页。
- 工具库通过首页「全部工具」进入，支持系统返回及页面返回。工具库的主任务使用同一视频导入操作，不多一层跳转和重复选取。
- 主页品牌长按 → 原彩蛋页；移除首页轨道和吉祥物占屏动画，不删除彩蛋资源／入口。
- 错误在当前触发页就地展示，保留可读的错误文案及重试能力；不得吞掉 `VideoImportState.errorMessage`。
- 不支持独立入口的编辑器内能力以静态能力说明表示，卡片不得响应点击；不展示「即将上线」作为可点击的任务。

### 视觉规范

| 维度 | 要求 |
| --- | --- |
| 基础色 | `AppTheme.flowBackground`／`flowSurface`／`flowBorder`；取消首页局部 `_HomePalette` 蓝色体系 |
| 强调色 | 使用 `AppTheme.gold` / `goldLight`，仅用于主卡视觉、重要操作与当前指示 |
| 首屏焦点 | 第一屏只突出视频隐私保护一张主卡；品牌与工具库入口处于次级层级 |
| 卡片 | 高度随设备动态调节，使用 `LayoutBuilder` 或等价约束，圆角与光影统一，不叠加装饰框 |
| 辅助文案 | 用用户能理解的效果描述，不承诺尚未验证的全自动保护成功率 |
| 吉祥物 | 从首页大面积视觉移走，仍可在现有彩蛋及适合的反馈场景中出现 |
| 动效 | 只保留必要的点击／页面转场；遵从系统减少动画设置，无持续旋转／浮动场景 |
| 平台 | Android、iOS 统一 Flutter 布局，安全区内无裁切；状态栏保持清晰对比 |

## 可扩展模型

- `ToolEntry` 表达 ID、标题、简述、图标、归类、能力状态；分开管理“独立可启动任务”和“编辑器内能力”。
- 首页主卡数据来源只包含独立可启动任务；工具库的编辑器能力列表不是独立启动任务。
- 后续出现第 2 张可用主工具卡时，才展示 PageView 页码及窥视边缘；数量较多时工具库负责全量发现。绝不把首页轮播当成唯一导航。
- 当前不引入远程模板、个性化算法、内容推荐、用户登录、持久化最近项目；避免用无内容模块填充首屏。

## 可访问性与验收

- 首屏主动作可由屏幕阅读器辨识为“选择视频，开始视频隐私保护”；图标装饰不重复朗读。
- 点击区域至少 48dp；标题、按钮、辅助文字在 320×568、360×640、390×844、较大屏和系统字体放大时不遮挡，不出现 RenderFlex 溢出。
- 首页与工具库的主操作必须调用既有 `pickAndProbeVideo` → `createProject`，并在编辑返回后清理导入状态；取消与失败行为不退化。
- 工具库不能出现可点击但无动作的卫星／功能入口；关闭动效时无持续动画。
- 首页 widget 测试不再验证五帧吉祥物动图，而改为验证新主卡、工具库入口、编辑器内能力的非点击属性、紧凑布局和 AppTheme 一致性。
- 至少运行针对首页的 Flutter widget 测试、`flutter analyze` 相关目标；如果机器环境阻断执行，必须准确记录阻断条件，不虚报通过。

## 分段提交计划

1. `docs: define card workbench home UX and acceptance`：本设计与验收规范；单独 commit。
2. `feat(home): replace orbit landing with focused hero card`：主卡布局、共享导入动作、品牌彩蛋与错误状态；单独 commit。
3. `feat(home): add tool discovery and future card registry`：工具库及类型化数据；仅真实独立工具为可启动项；单独 commit。
4. `test(home): cover card navigation and compact layouts`：widget 测试、静态分析、文档复核；单独 commit。

所有提交仅留在 `feat/home-card-workbench` 独立 worktree。未获指示不合并、推送或修改 master。
