# Android 对比页：自动校准与双播放条手动校准

## 本轮结果

按当前用户要求完成正式 Android 页面调整，已经安装到当前手机。保留黑金主题和正常模式下的共同音频时钟、双 MediaCodec、单 GL 合成，改动集中在对比页面与校准流程。

- 选片完成或恢复未校准的视频组合后，自动匹配音乐并采用最佳可用结果；界面不再展示候选列表或试听候选入口。
- 已有校准的组合继续使用原结果，重新关联同一文件不会无故重跑。
- 正常页入口改为「手动校准」。进入后，两段视频各有独立播放、源时间进度条和前后 0.1 秒微调；底部共同进度与共同播放控件隐藏。
- 「完成校准」取两段源时间之差，保存锚点并恢复共同播放；「取消」恢复进入前的校准和共同位置。保存失败会保留编辑状态。
- 主页面保留大播放按钮、共同进度与倍速。短片前后跳转为 1 秒，长片为 5 秒；片尾显示「重播」。
- 文件名从常驻选片卡片中移出，通过来源提示和项目列表查看；项目入口带文字，保存/重命名与新建收进更多菜单。

页面字体、黑/石墨背景、白色文字、金色操作色沿用 AppTheme。按钮与播放条使用现有 Material 组件，没有加入新图标包、字体或外部图片。正常播放的时间数字使用等宽数字特性；大字体下简化时间并重新安排倍速，避免主要控件拥挤。

在本轮过程中，用户在手机上更换了学生素材。早期同素材对比使用 +1.490 秒；后续截图保留用户当前所选的竖版素材与 +1.450 秒结果。媒体内容和偏移差异不属于样式误差，没有为视觉对照把素材换回旧文件。

## 交互与数据

自动匹配结果仍由设备端音频分析产生，页面直接采用评分最高且具有公共视频区间的结果。证据不足但存在可用位置时标记为自动微调状态；没有可用音乐时保留手动入口，不生成虚假的成功结果。算法内部仍可分析多个位置，但它们不出现在产品界面。

手动模式复用 app 已有 video_player。进入前暂停并保存共同会话、关闭共同解码器，再创建两路独立预览；播放其中一段时暂停另一段，便于分别听取鼓点。拖动预览合并为最近的 seek，避免积压请求。未确认的拖动不写入项目。

退出手动模式时先移除两路预览 widget，等待当前帧完成，再释放播放器并重建共同 GL 会话。这样避免旧纹理仍在渲染树中时释放底层资源。项目格式仍为现有本机 JSON；正常播放的位置、速度、校准方式与锚点继续保存。

## 验证证据

1. **正常比较页 — 通过**：无候选列表，视频画布更大，播放、1 秒跳转、变速和片尾重播可用。
2. **自动选择 — 通过定向测试**：新组合/未校准恢复会自动运行，采用评分最高的可用结果；取消和已校准同文件重新关联会保留现有结果。
3. **独立手动播放与拖动 — 真机通过**：老师播放到 2.154 秒时学生保持 1.450 秒；老师拖到 9.140 秒时学生仍保持 1.450 秒；学生拖到 11.225 秒时老师保持 9.140 秒。
4. **完成与取消 — 真机通过**：取消后恢复原 +1.450 秒；完成测试保存老师 0.100 秒、学生 1.550 秒，差值仍为 +1.450 秒，共同进度恢复。
5. **切换后共同播放 — 真机通过**：连续执行取消和完成后，页面进度从 2.393 秒更新至 4.676 秒，按钮、进度和语义树均正常。
6. **项目与可访问性 — 范围内通过**：保存失败保留编辑状态、原校准可恢复；控件最小触控尺寸检查、320×640 小屏和 2 倍文字测试通过。未宣称完整 TalkBack 合规。

这些手动时间用于验证独立定位、差值保存和播放恢复，不是新增的人工音乐/鼓点精确标注。真机复用已经授权的当前来源；没有要求再次选片或确认新锚点。

Flutter 全套 94 项通过。切换修复后，对比专项 14 项再次通过，新增了预览 widget 必须先移除再释放播放器的回归约束；两个数量有重叠。最新 flutter analyze 无问题。复用了未改动模块结果，未执行全量 Release QA。
