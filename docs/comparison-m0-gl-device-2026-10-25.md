## 实现与关键修复

唯一的 Media3 1.9.2 音频播放器只选择老师音轨并禁用视频轨，两路视频由各自 MediaExtractor / MediaCodec 解码。音频位置映射到老师 `T` 和自己 `T + offset`，按实际源 `[PTS, nextPTS)` 区间选帧。两个 SurfaceTexture 均锁定且校验时间戳后，在同一个 EGL window surface 内绘制上下两幅画面，只进行一次 `eglSwapBuffers`。任一路未就绪都不会单独提交半幅新画面。

seek 会暂停共同音频，递增请求代数，取消旧请求，flush 两路 codec，待新目标的双路帧完成后再恢复。播放队列只有一个执行请求与一个最新请求，避免旧时钟任务排队。50ms 渲染看门狗暂停唯一音频，双路追上冻结后的主时钟后共同恢复。暂停期间窗口尺寸变化也会重绘已锁定的帧对，修复早期 EGL 旧尺寸 buffer 被丢弃而黑屏的问题。快速连续 seek 曾暴露 SurfaceTexture 合并通知导致的等待超时；最终版在取消后消费遗留图像，并同时轮询实际纹理时间戳与回调信号，避免把已丢弃的通知当成尚未到帧。首次零 PTS 还要求出现真实生产者通知，防止空纹理的默认零时间戳冒充首帧。

本机公开 `ExoPlayer.currentPosition` 有约 10/20ms 发布阶跃，直接按显示 VSYNC 取值会导致 60fps 重复/跳过目标帧。锁定依赖的字节码证实非 offload 分支直接读取已发布的 `PlaybackInfo.positionUs`。最终用单调时间对这唯一音频位置作有界插值：最多领先公开位置 15ms，暂停、seek、缓冲和变速即丢弃锚点，不产生独立的视频自由时钟。输入预填充没有改善性能，已回退。

1080p60 联合提交率由早期约 46.5fps，经纹理并行锁定与最新请求合并改善到约 50.8fps，最终为 **57.98fps**。最终 P95 渲染耗时 13.945ms、解码准备 9.828ms、纹理锁定 3.600ms、EGL 交换等待 1.294ms；仍有少量跳帧，不宣称无损 60fps。无录屏的同源 1080p60 对照为 58.22fps（联合提交元数据），用于区分采集开销，不替代录屏像素证据。

## 固定 APK 的稳态真机数据

所有同帧率 CFR 场景同时要求：独立元数据评估通过、录屏逐帧码评估通过、无歧义帧码、无帧覆盖失败、无非注入渲染停顿。原生诊断剔除 epoch 起首约 1 秒墙钟时间；录屏按源时间过滤（24fps 负偏移长片取老师 [2,121)s），慢速播放时两类样本范围并不完全相同。录屏可以包含保持帧，因此有效录屏样本数不等于源视频帧数。

| 24fps / -1s / 短片 | 1× | 239 | 228 | 0 / 0µs |
| 24fps / -1s / 短片 | 0.75× | 244 | 245 | 0 / 0µs |
| 24fps / -1s / 短片 | 0.5× | 249 | 274 | 0 / 0µs |
| 24fps / -1s / 120s音乐 | 1× | 2879 | 3060 | 0 / 0µs |
| 24fps / -1s / 120s音乐 | 0.75× | 2884 | 3248 | 0 / 0µs |
| 24fps / -1s / 120s音乐 | 0.5× | 2890 | 3687 | 0 / 0µs |
| 30fps / +3s / 短片 | 1× | 329 | 308 | 0 / 0µs |
| 30fps / +3s / 短片 | 0.75× | 335 | 328 | 0 / 0µs |
| 30fps / +3s / 短片 | 0.5× | 342 | 350 | 0 / 0µs |

以上 10 组 CFR 共 **12296 个有效录屏帧对**、11027 次稳态联合提交；所有组可见源 PTS 差（减去音乐偏移）的 P95 / 最大均为 **0 / 0µs**，无效帧码及原生帧覆盖失败均为 0。24fps／−1s 的三档长片共同区间为 121s，音乐为 120s；逐个 5 秒窗口的误差均为 0，没有观察到累积漂移。原后端在该 24fps／−1s 场景的 P95 / 最大约为 83.333ms。

混合 24/30fps 和 VFR 另按 FFprobe 的实际帧区间评估：

| 场景 | 有效帧对 | P95 / 最大区间间隙 | P95 / 最大帧起点差 |
|---|---:|---:|---:|
| mixed-24-30 | 412 | 0 / 0µs | 33.333 / 33.334ms |

## 交互、缓冲与生命周期

- 30fps：16 项截图观察全部满足各自断言，包括 0% / 50% / 90% seek、±10 秒、±10ms / ±100ms 偏移恢复、快速连续 seek 的最终请求、暂停保持、后台返回以及播放中 seek 后继续运行。
- 24fps／−1s：0% / 50% / 90% / 回到 0% 的帧对分别为 [24, 0], [156, 132], [261, 237], [24, 0]，符合公共区间映射。
- 0.5× 暂停位置 [180,270] 经横屏、竖屏恢复仍为 [180, 270]，偏移与速度保留；横屏截图同时存在两路视频背景像素。
- 同一 Activity 连续 3 次 Home / 返回，每次两路帧保持，源错误与引擎关闭失败计数均为 0；观测 PSS 为 116323, 126358, 126713KB。这是有限次资源回归，不是无限期内存泄漏证明。设备旋转设置已恢复原值。
- 24fps／−1s 的 10 组不同方向快速跳转全部收敛到最后请求，帧码均保持 24 帧差；播放时进入 Home 后返回为暂停状态，保持一秒不变，手动恢复后两侧继续前进。
- 注入前后帧对由 [60, 150] 推进到 [135, 225]，两侧在恢复后均继续播放。

受控 150ms 渲染饥饿用 Debug 专属广播触发，独立于正常性能统计。该轮报告显示 1 次渲染停顿、1 次注入；共同音频暂停后自动恢复，两侧帧号继续前进，录屏误差仍在门槛内，没有源错误或帧覆盖失败。此用例验证恢复路径，不把人为停顿计为正常播放流畅度。

本次采集无需用户手动选片或手机授权。只替换本应用专属目录中的合成测试片，未卸载、未清除应用数据，未清理其他工作区。

## 使用与后续边界

uv run python tools/comparison/run_m0_android.py --backend shared-gl `
  --teacher docs/session/comparison-m0-20261025/fixtures-24-negative/teacher.mp4 `

本结论是**所测设备、所测合成素材矩阵的 M0 通过**：具备可复验的真实设备解码、GL 提交与编码合成画面证据。录屏不等于物理面板扫描测量；没有外部高速拍屏或声学输出延迟测试，不承诺所有设备、所有媒体格式或真实舞蹈素材均通过。自动共同歌曲识别、动作评分、导出、iOS 与 M1 均未开展。
