# Woah M0 · 手动音乐锚点与原生不同帧率真机验收

**本机手动近似锚点与原生不同帧率播放调度通过；长时真实原片仍待素材。** 用户确认“老师 0 秒对应学生约 2 秒”，因此应用 `offsetUs=+2000000`。这是人工粗校准，不代表音乐、声学或物理屏幕达到毫秒级精度，也没有进入 M1。

## 手动校准与持久化

`143e493 feat(comparison): 添加可确认并恢复的手动音乐锚点` 增加 Debug 输入框：分别输入同一音乐事件的老师、学生源时间，先预览 `学生 − 老师` 和公共区间，再确认应用。支持秒或 `分:秒`，最多六位小数；校验源时间在视频内部、偏移不超过 ±300 秒。微秒是保存单位，诊断仍明确标为用户估计、精度未经独立测量。

真机已验证：无效时间不会应用；`0 / 2` 预览和映射正确；冷启动恢复 +2 秒；−100ms 微调变成 +1.9 秒并清除锚点确认；该状态可恢复；清除校准后恢复为 0；重新输入 `0 / 2` 再次恢复 +2 秒。只在应用私有 `noBackupFilesDir` 记住对应选片对，换任一路时归零，显式测试参数不继承或覆盖原片校准。

## 修复真实 4K seek 故障

第一轮原片交互在公共区间约 20%（老师约 3.574s、学生约 5.574s）触发 `Decoded frame does not cover requested source PTS`，该轮未计为通过。日志与失败截图保留在 `original-controls-failed-143e493/` 和 `controls-failure-logcat.txt`。

`c22b531 fix(comparison): 校验并回退越过目标的同步采样点` 在 seek 后检查实际同步样本 PTS；晚于目标则有限次向前回退，并向前解码到**原请求时间**。严格的帧区间覆盖和实际 SurfaceTexture PTS 校验保持。不是显示未来帧，也没有靠扩大同步误差阈值消除异常。

同一位置在修复包上成功复现防护：学生 `learnerSyncSeekRetries=1`、老师 0，源错误为 0。随后完整 18 项交互通过，最终计数仍为学生 1 次回退，覆盖失败、渲染停顿、资源关闭失败均为 0。

参考 Android 的 [MediaExtractor 同步点模式](https://developer.android.com/reference/android/media/MediaExtractor#SEEK_TO_PREVIOUS_SYNC) 和 [MediaCodec seek 后的流边界要求](https://developer.android.com/reference/android/media/MediaCodec#seeking)。仅在落点晚于目标时增加回退；正常先行同步点路径不变。

必须区分不同指标：30／约59.94fps 的自然帧起点不相同，不能要求帧起点差为零。逐源灰度参考只将录屏各侧匹配回各自源文件，不做人物之间的动作匹配，也不用时间先验。三档基线有 **3141 / 3145** 个主体帧对满足筛选，4 个歧义对排除；修复后复核为 **906 / 908**，2 个歧义对排除。

首轮 32×64 参考的固定 33.334ms 帧起点差判据**未通过**。提高至 64×128 后，基线估计帧起点差 P95 仍为 38.856–41.456ms；它混有自然帧网格差与相邻帧识别误差，不能改称精确可见同步通过。实际 PTS 区间的参考估计间隙 P95 为 7.989–12.233ms、最大 30.811ms，在老师一帧约 33.334ms 的参考识别不确定性内。修复后区间估计 P95 / 最大为 8.567 / 30.111ms。结论保留这一精度限制，物理面板扫描与声学延迟均未测量。

## 交互、压力与负偏移回归

- 修复包完成 **18 项**原片观察：0 / 50 / 90% seek、±10 秒、三组连续 seek、暂停保持、三次 Home / 返回、手动续播、播放中后台恢复为暂停、0.5× 播放中 seek。逐源参考均在目标一帧内，没有需要单列的视觉歧义。
- 暂停期间两侧截图哈希保持；后台返回后无自动单边续播。0.5× 播放中 seek 后暂停约为老师 9.667s、学生 11.667s，映射保持 +2 秒。
- 基线 `143e493` 在同一原片对上完成 **17 轮**重复播放，计划播放累计 **333.553s**、原生稳态观测累计 **318.634s**、联合提交 **17396**。覆盖失败、渲染停顿、关闭失败均为 0。暖机后 PSS 中位数增加 **4550KB（约 4.4MiB）**。每轮从老师 0 / 学生 2 秒开始，该落点的同步 PTS 已先于目标；新防护对该路径无改变，因此复用这份有效基线，不把它声称为修复包的新 17 轮实测。
- **重复短片不等于长时原片**：每轮源时间重新从头开始，不能证明连续长视频漂移，也不足以证明没有内存泄漏。
- 修复包复用既有 24fps / −1s 合成输入作参数覆盖回归：235 个有效录屏码对，P95 / 最大误差 0 / 0µs。之后无参数冷启动回到手机 4K 原片、+2 秒和已确认锚点。素材文件本身是既有 120 秒样片，但本轮只采集短段回归，不冒充新的长时验收。
