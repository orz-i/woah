# Woah M0 · 手机真实舞蹈素材播放调度验收

**结论：本机、所选素材的播放调度门通过。** 用户确认先用 `offsetUs=0` 验收播放、seek、变速和后台恢复；**音乐内容对齐未校准**。本结论不等于两段音乐已经同步，不进入 M1。

- [完整机器数据](comparison-m0-real-device-2026-10-25.json)。原始本地证据在 `docs/session/comparison-real-m0-20261025/`；媒体、截图、音频数值和特征数组遵循现有忽略规则，不进入 Git。汇总只使用匿名角色、流参数和哈希，不含原文件名或媒体 URI。本地 `evidence-index.json` 固定 208 个文件、183,285,472 字节；索引 SHA-256 为 `457837779e75b6132e8733f1df6d90f0fd56b5afbc150fde7c39bf419e2f7d44`，不包含未采用的 PC 候选输入。

## 不同帧率与 VFR：真实画面派生副本

原片均为 30fps，故不同帧率覆盖使用明确标记的派生输入。它们保留全部原画面，在底部追加 64 像素帧码页脚后编码成 HEVC Main；不是原生 24/60fps 摄像机采集，也不会增加原视频的动作细节。音轨直接复制，五个副本解码后的 PCM 与各自原片逐字节相同，没有音频时移。

- 老师固定 30fps；学生分别为 30fps、24fps、60fps、VFR。60fps 由 30fps 画面复制得到；VFR 在 30fps 基础上按固定模式丢帧，保持原 PTS，间隔包含约 33.333ms 与 66.667ms。
- 五个输入副本均完整解码，并逐帧核对页脚码与实际 FFprobe PTS 对应；不存在只生成文件头就记为成功。
- 录屏按真实画幅和页脚位置裁剪，使用实际 `[PTS,nextPTS)` 区间评估。不同帧率的自然帧起点差不能套用固定 33ms 偏差判据。

## seek、变速与后台恢复

原片完成 **18 项**观察，逐源画面参考均在目标帧一帧范围内，无需要单列的视觉歧义：

- 0% / 50% / 90% seek：源时间 0 / 8.950 / 16.110s，对应帧约 0 / 268 / 483；±10 秒跳转正确。
- 三组不同方向的连续 seek 均收敛到最后请求；没有旧 seek 覆盖新目标。
- 暂停一秒两侧画面哈希保持；连续三次 Home / 返回，位置保持 1.986s，画面参考均为源帧 59，手动恢复后推进到约 3.983s / 帧 119。
- 播放中进入 Home 后返回为暂停，保持一秒不漂移；没有自动单边续播。
- 0.5× 播放中 seek 到 8.950s 后，两侧恢复前进，暂停核验约 9.666s / 源帧 289，没有黑屏、超时或源错误。

手机选片引用仅记在应用私有 `noBackupFilesDir`。冷启动已验证能恢复这两段原片，派生素材的显式测试参数不会覆盖记住的手机选片。输入采集要求 ADB 的系统 `DUMP` 权限，仅复制当前选中的两段媒体到本地工作目录，不扫描相册、不修改原视频、不上传原音视频。

- `016c1dc`：补齐仅 Debug 的手机选片记忆、带哈希的本地输入采集，以及失败/取消不发布部分文件的保护。这是本轮实测 APK 源码。

- 新增 `prepare_m0_real_fixtures.py`：标准库页脚绘制、流式处理真实画面、HEVC 副本、24/60fps 与 VFR 输入；整目录原子发布，失败不发布半套素材。
- `analyze_m0_screenrecord.py` 支持实际截图中的两路帧码矩形；`--codes-only` 只提取码值，交给真实 PTS 区间评估，避免对异帧率输出错误的等帧率误差。
- 原生比较测试 **23/23**；Windows、WSL Linux、macOS 工具测试各 **27/27**。历史 1080p60 录屏用新分析器复算，568 个有效样本及全部既有指标不变。
- 首轮空样本与 UI 空闲等待误判没有计入通过数据。播放状态持续更新时，UIAutomator 可能无法等待空闲或留下旧布局；采集改为暂停时定位控件、播放中通过原生联合提交增长确认启动。失败尝试单独保留。
- 同步时钟、双解码器和 GL 合成实现本轮未改动，沿用已验证的后端；原隐私处理、Flutter 首页、iOS 不变。

## 边界与下一步

通过范围是**这台设备、这两段原片及其明确标记的派生输入的零偏移播放调度**。没有测试原生拍摄的 24/60fps 或其他设备；真实原片公共时长只有 17.9s，不宣称长时真实素材漂移结论。编码录屏不是物理面板扫描测量，也没有声学延迟测试。

下一步仍留在 M0：在用户给出明确音乐锚点后做手动恒定偏移校准，并补原生不同帧率、VFR 和更长真实片段的抽验。当前不启动自动音乐匹配、动作同步或其他 M1 功能。
