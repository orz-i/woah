# Woah 实际代码治理审计

**审计日期：2026-10-31 UTC。基线：`master@0aef51eab4ef8a8a65f29e83883b87ca1de77e46`。**

核心结论：现有分层和测试值得保留，但“Production CI 成功”还不能代表项目可合并、双平台可交付。当前主分支 iOS 构建失败；两个导出状态机缺陷已通过隔离测试复现；原生资源交接、未打码缓存保留、主线程文件复制等路径缺少完整生命周期约束。建议按[整改台账](remediation-plan.md)先恢复门禁，再修缺陷，最后渐进拆分职责。

## 审计范围和证据等级

本次读取了 Flutter app 与三个包、Dart 状态和路由、Kotlin / Swift bridge 与媒体管线、Pigeon schema、GitHub 工作流和设置、Python 桌面入口及模型加载链、依赖锁和现有文档。代码审计开始时工作区干净，HEAD 与远端基线一致。

- **已复现**：实际运行得到失败断言或当前 CI 编译错误。
- **静态确认**：代码路径和配置可直接证实；运行时影响需要特定条件。
- **高置信风险**：存在可行竞争或缺少闭环，但未做真机故障注入。
- **待核验**：需要最终产物、设备或权限验证，不作为已发生故障。

没有启动桌面服务器、执行真实视频导出、访问用户媒体、安装依赖或更新工具链。没有在本机完整执行 Android / iOS 构建，也没有把静态验证当作设备验证。远端构建结论来自已有 GitHub Actions 运行记录。文档以只读审计和临时隔离测试为基础，不是渗透测试或商店合规认证。

## 具体证据

### GOV-01 当前 iOS 编译失败且合并约束缺失

[PR #6](https://github.com/orz-i/woah/pull/6) 的 head `a44d769` 在 01:57:16 UTC 已出现 iOS 失败，随后于 01:59:22 UTC 合并为本次基线。当前 master 的 iOS 运行再次在 [IOSComparisonMusicFeatures.swift 100–110](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/packages/dance_native/ios/dance_native/Sources/dance_native/IOSComparisonMusicFeatures.swift#L100-L110) 报告第 107 行编译器无法在合理时间内完成表达式类型检查。PR head 与 master 的该文件 blob 相同，因此不是只引用历史红灯。

GitHub API 实查：仓库公开，可见 collaborator 为 1；`master.protected=false`，rulesets 列表为空，branch protection 接口返回 404。由此可确认当前未建立阻止该失败合并的主分支保护，而不是猜测私有设置。

建议先拆分 Swift 复杂表达式并补明确类型，重新通过 Phase 6 simulator gate 和生产 iPhoneOS no-codesign build；门禁自身稳定后，再经维护者批准启用 required checks。单维护者可以采用 PR 自审加强制自动检查，不要求不存在的第二位评审者。

### GOV-02 现有 CI 不是完整质量门禁

[Production CI](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/.github/workflows/ci.yml#L9-L98) 已跑 Python 工具、Flutter 测试、Android native unit test、Release Kotlin 编译和 Debug APK 构建，值得保留；但没有 Dart 分析、格式检查和 Android lint。构建并不自动等价于 Android lint。

[iOS 路径过滤](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/.github/workflows/ios-cloud.yml#L6-L23) 未包含 `dance_ui/**`、`tools/ios/**` 及完整 `tools/release/verify_ios_phase*.py` / 对应测试等实际输入。工作流直接调用 phase4；[phase1 的环境分支](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/tools/release/verify_ios_phase1.py#L255-L268) 还在 macOS 且 `GITHUB_ACTIONS=true` 时隐式调用 [phase6 gate](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/tools/ios/run_phase6_macos_gate.py#L61-L98)。该 gate 又读取 phase2–6、编译 Metal、构建 `ios_phase6_smoke_main.dart` 并跑 simulator smoke。因此不能写成“没有 iOS 原生构建”，实际问题是入口命名与完整依赖图不透明、路径覆盖不足。

建议明确画出 gate 调用图，按读取/执行依赖维护变更分类。常驻 required-check 汇总 job 必须每次 PR 都上报，并正确传播失败/取消；不要把可能被 workflow 级 `paths` 跳过的检查直接设为必需项，否则可能一直 pending。

### DART-01 重试启动窗口取消旧任务

[startExport](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_controller.dart#L99-L140) 先复制旧 state，等待 RPC 后才替换 job ID；[ExportState.copyWith](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/domain/export_state.dart#L59-L90) 的 `jobId ?? this.jobId` 无法清空旧 ID。[取消按钮](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_screen.dart#L180-L188) 只以 job ID 非空决定可取消，[cancelExport](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_controller.dart#L175-L181) 使用该 ID。

隔离复现顺序为：第一次失败 → retry 的新 RPC 挂起 → cancel → 新 RPC 返回。实际取消目标为旧 `preview-toggle-job`，最终 state 为 `jobId=second-job` 且 `status=cancelled`。这是控制器行为已复现；未在真机证明新 native job 一定继续运行。

修复应使用新 generation / 明确启动阶段，重置旧 job、输出和终态；对“尚未取得新 job ID 的取消”有延迟取消或明确不可取消契约。只在 UI 禁按钮不能处理晚回包、旧事件和资源接管。

### DART-02 页面销毁后启动回包访问失效状态

控制器为 [autoDispose provider](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_controller.dart#L1-L18)；[异步启动与 catch](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_controller.dart#L110-L151) 在 await 后没有 generation / 生命周期检查，catch 又访问 state。[页面启动](https://github.com/orz-i/woah/blob/0aef51eab4ef8a8a65f29e83883b87ca1de77e46/mobile/app/lib/features/export/presentation/export_screen.dart#L53-L60) 没有处理启动 Future，且页面未见针对该窗口的 PopScope。

隔离测试中 pending → dispose → complete，会出现 `Tried to use ExportController after dispose`，随后 catch 再次失败。该结果来自 debug 测试，不能推断所有 release 构建均以相同方式崩溃。修复除避免失效 state 访问，还须取消、释放或移交已经提交的 native job，不能简单 return 留下孤儿任务。
