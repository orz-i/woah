# Woah 冻结治理路线图：G1–G3

**范围版本：2026-10-31。产品目标仅 Android / iOS；桌面 / Web 废弃。** 维护者要求先完整规划、避免阶段膨胀，随后授权按既定目标处理仓库。此文件是阶段范围的唯一来源；[整改台账](remediation-plan.md)保留 15 项发现的唯一归属与证据，[工程规范](engineering-standard.md)保留开发原则。审计历史不重写。

## 目标、授权与明确非目标

本轮只建立：可信的检查与合并证据、移动资源／隐私生命周期闭环、可复现的移动构建与发布材料。

- 常规代码／文档提交、push、PR 创建及检查通过后的正常收口合并已获授权；不重复询问每个常规步骤。
- 不绕过红灯，不使用管理员强制合并，不代提交 approving review。安全敏感设置、凭据／持久访问、产品策略或范围改变仍需相应明确确认。
- G1 完成后必须报告实际验收与 G2 的产品决策缺口；本次 G1 任务不自动开始 G2 实施。
- 不清零全部 lint warnings，不全量重写架构、不换状态库、不以治理名义大版本升级；不新增网络桌面产品，不删除历史源码／分支／许可证，不停服务，不新增凭据。
- 89 条已有 lint warnings 是分类台账，不是扩张后的完成目标。新增或受影响警告须解释；确认的新独立缺陷进入范围变更，而非自动纳入本阶段。

### G1 阶段卡

**进入条件：** 范围冻结；PR #7 已合并；PR #8 的精确 head 验证可审计；维护者已授权正常仓库收口。

**固定交付：**

1. 保留 #7 的 Swift 编译修复及 19 项导出状态回归，#8 的 format／四包 analyze／显式 lint／完整双平台及 fail-closed 汇总。
2. #8 复核当前 head、检查、评论及合并条件后正常合并，验证 merge 提交。
3. 唯一文档 PR 固定本路线图和阶段卡、同步台账、撤下桌面部署宣传并标注历史目录；保留源码与共享工具。
4. 只读核实服务器规则，保留最小设置提案。维护者明确本轮不启用、待本轮结束再评估（G1-EX-01）；不应用、不再逐项询问，也不阻止 G1 收口。

**验收：** 文档独立审查；相对链接与 15 项映射无遗漏／重复；diff 只有文档；文档 PR exact head 的 Production CI 三个检查成功后正常合并，再验证 merge SHA 的 push CI。失败／取消／意外 skipped 均不得当作通过。

**退出与停止：** 上述工程与文档证据齐全即停止实施并报告。服务器保护未启用、DART 真机／持续平台调用失败等残留须原样记录，不能以“G1 工程交付完成”宣称这些发现全部关闭。当前取消实现的边界（RPC 永不返回 ID、持续取消调用失败）不是无限重构任务，需在后续原生契约中有针对性处理或明确支持限制。

**非目标：** 不实施 G2；不修改 desktop 运行代码、依赖锁、模型或 CI 以进行退役；不修复每条警告；不自动改权限。

### G2 阶段卡

**进入条件：** G1 基线在主分支可用；明确本阶段设备／模拟器验收矩阵与实际缺口。涉及缓存保留、用户删除语义、TTL／配额的实现须先冻结策略；缺策略或真机只阻塞相应验收／决策依赖，不阻塞其他确定性测试设计与已授权切片。

**四个有限 PR：**

| PR 切片 | 交付 | 依赖与最低验收 |
| --- | --- | --- |
| G2-A / NATIVE-01 | preview 与 export 的资源 owner、借用／drain／取消完成约定 | 确定性暂停写入／提交窗口，验证无 recycled Bitmap、已关闭 buffer、shutdown 后提交、重复终结；保留既有同 executor 序列化；既定 Android 设备快速切换／导出／取消回归 |
| G2-B / NATIVE-02 | Android 相册写入离开主线程，失败／取消只终结一次并回滚本次新建条目 | 慢 I/O／StrictMode，磁盘满、读写失败、权限失败、取消／detach 注入；无 pending／空媒体残留，源文件不变；不引入完整后台调度框架 |
| G2-C / PRIV-01 | session 完成／放弃／替换／删除与缓存释放、重启孤儿清理、有限空间 | 依赖 G2-A 的在用保护及已批准缓存策略；按既有建议 100 次合成导入／放弃压力用例验证已批准上限、重启清理和在用不误删；100 次是项目用例，不是通用官方标准 |
| G2-D / PRIV-03 | 错误码与日志脱敏边界，覆盖嵌套 error／诊断包 | 合成 path／URI／文件名不可检出，同时仍可定位错误阶段；不上传真实媒体、不中断现有可诊断性 |

**固定安全边界：**

- NATIVE-01 的“完成”取 worker 真实 finally／drain，而非 cancelled 通知；export 期间不得由新 preview 重新抢占同一 GPU owner。Bitmap 用锁内 copy 或实际借用期，不返回可能马上 recycle 的裸引用。
- NATIVE-02 事务只拥有本次 insert 的目标 URI，复制、关闭流、发布失败或 detach 取消只回滚它；不删除源文件或旧相册内容，main 回调恰好一次。
- PRIV-01 的 session 跨选择→编辑→导出，页面 dispose 不是释放所有缓存的依据。release 只表达意图，analysis／preview／导出真实 lease 归零后才删；晚回包清理自己拥有的结果，重复 release 幂等；启动先确认活动导出再扫孤儿。
- 缓存清理白名单仅 app 自建、可再生的 analysis／preview／trim；路径规范化并拒绝逃逸。排除原始媒体、最终导出、用户贴纸、profile、comparison 项目库、模型和诊断历史，不扩成整个 cache 的清理。
- 孤儿 TTL **24 小时**、非活动缓存软预算 **256 MiB** 仅是待确认／待测试的内部初值提案，**未批准、未实施，不是冻结产品承诺**；活动资源永不强删，正常 release 的生命周期语义不能被 TTL 取代。若影响持久项目恢复或不可再生内容，必须先报告方向决策。
- PRIV-03 覆盖 Dart、原生异常及诊断文本／bundle 出口，使用错误码和白名单字段，不新增遥测。测试包含 content/file URI、跨系统路径、Unicode／空格／编码文件名和嵌套异常。

**验收入口：** 每个切片新增失败回归并在修改后通过；现有四包测试、原生单测／lint、完整 iOS gate 和 APK 保持通过，独立审查后核验 exact-head CI。2026-10-31 06:16 UTC 的只读检查中 `adb devices` 无设备；Android GPU／MediaStore 真机验收目前未执行，不能用 JVM／模拟器绿灯替代。硬件缺口集中报告，不通过扩大实现或降低门槛掩盖。

**退出与停止：** 四个切片各自通过冻结的正常、失败、取消、释放用例后停止；设备不可得或策略未定时标“待验收／阻塞”，给最小解除条件，不用新增重构填补。新问题先登记，超预算或独立目标不得自动实施。

**非目标：** 不全量替换 GPU／线程模型，不保证所有外部 RPC 永不失败；不增加云端媒体上传、账户系统或未批准缓存保留规则。

### G3 阶段卡

**进入条件：** 主分支质量基线可信；工具／解析器及发布材料范围明确；GEN-01 在生成器版本锁定后实施。可以只读调查依赖，不跨阶段并发修改。

**最多四个 PR：**

1. DEP-01 工具版本与 Actions／uv 固定：沿用已验证版本，核实可用的官方 lock／完整 SHA 方案；不自动升级到“最新”。
2. DEP-01 实际移动解析锁及仍用 Python 模型工具边界：先识别 CocoaPods／SPM、Gradle 的真实解析链再锁定；根 Python 环境仅按仍用工具判断，排除已废弃桌面安装交付。不是删除全部 Torch、Ultralytics、Python CI 或模型源权重。
3. GEN-01：两 schema、Dart／Kotlin／Swift 六份产物的统一生成入口；连续生成两次无非预期差异，故意改 schema 不提交产物时 CI 必须失败；不手改生成文件。
4. PRIV-02：真实调用用途、API／原因码、组件归属和最终 archive 的 manifest 检查。候选原因必须与实际使用吻合，不能复制原因码了事。

**验收：** 干净环境重复解析与生成，无非预期 diff；现有 exact-head 双平台检查保持通过；模型契约不漂移；实际打包产物 manifest 可追溯。源码正确但产物未核验不关闭 PRIV-02；无正式发布环境时保留发布阻塞，不宣称商店发布就绪。

**退出与停止：** 四项有限交付满足即停。大版本兼容迁移、弃用工具替换、额外平台、新凭据／权限或成本变动必须另行决定，不用增加 PR 伪装为本阶段细化。

**非目标：** 不建设桌面 Mac／Windows 安装路径，不全库依赖升级，不启用自动依赖合并，不扩大签名或商店权限。

## 范围变更与工作上限

1. 每阶段只维护一个在制实现 PR；只读调查／独立审查可以并行。一个 PR 处理一个可测试行为契约，格式、依赖变化与业务修复分开审查。
2. 新发现先记关联 ID、证据、是否阻断当前固定验收、最小修复和预算影响。纯属既定交付的必要修正可在原切片内处理；独立功能、其他平台或预算外工作必须另列并获批。
3. 若需要超过 G2 的 4 个或 G3 的 4 个 PR，停止扩大范围，说明拆分原因、保留／退出项与新预算。不能创建“第 4.1 批”绕过上限。
4. 所有验收区分通过、失败、未运行、外部阻塞；不降低阈值、宽泛 ignore、刷新 golden 或取消检查来完成阶段。
5. 常规提交／push／PR 收口不反复询问；遇安全敏感动作、产品保留／删除决策、重大阻断、方向或范围改变时确认。每阶段完成必须报告。
6. 停止条件是固定交付验收通过，而不是“没有任何可优化之处”。架构长文件、工具新版本及 89 条历史警告不能无限续期开工。

## G1-EX-01：仓库保护本轮明确延期

2026-10-31 只读 API：`master` 未 protected，rulesets 为空。GitHub Actions 已产生稳定成功检查 `governance / required`（app slug `github-actions`，ID `15368`）。

维护者于 2026-10-31 明确决定：**“本轮治理暂不开启，待本轮结束后再评估。”** 因此保护规则不是本轮 G1 的阻断条件，本轮不应用、不重复请求。负责人／批准角色为维护者，关联 GOV-01 服务器门禁子项。

- 风险：虽然 CI 汇总存在，服务器尚未强制要求该检查及 PR 合并路径；人工遵守流程不等同于权限层阻断。
- 补偿：本轮仓库操作继续独立审查、精确 head 三检查成功后正常 PR 合并、merge SHA 复验；不使用管理员绕过、不 force push、不删除分支。
- 复评触发：G1–G3 本轮结束或提前终止本轮时统一评估；延期不自动延续到下一轮。用户没有指定日历到期日，不虚构时间承诺。
- 这是范围／设置延期，不授权红灯绕过、关闭检查或忽略安全风险，GOV-01 该子项仍未实施。

以下保留为**本轮结束时的待评估提案**，不是当前执行指令：仅针对 `refs/heads/master` 的 active ruleset：

- 要求经 PR 合并；单维护者所需 approving review 数为 0，不建立不可满足的第二人审批要求。
- 必需检查仅固定 `governance / required`，限定 GitHub Actions 来源；要求与最新 base 同步后成功。该汇总已经直接依赖 Android／质量检查与完整 iOS。
- 禁止 force push 和分支删除；不增加常规 bypass。
- 不要求新增签名凭据、不改 Actions 写权限、不建 token，不启用 auto-merge。

若本轮结束后决定启用，届时仍需具体安全设置确认；一般仓库授权不替代该确认。本轮保持未启用，不把 G1-EX-01 当已生效的保护或 G1 阻断。未来验证配置也不得对真实 master 尝试删除或 force push。
