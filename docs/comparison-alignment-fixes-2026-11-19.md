# 舞蹈对比：自动音乐校准修复

## 行为

- 固定偏移和恒定变速仍使用共享 Rust 音乐特征，不使用舞者动作作时间依据。
- 自动应用前，以连续短窗口核验共同区间，包含首尾。存在明显的局部不同步时，不再依赖三个大窗口的平均结果。
- 近等速候选出现局部漂移时，重新拟合原乐段的速率，并再次核验；不靠缩短共同区间绕过失败片尾。
- 无法用单一偏移/速率解释的剪辑跳变返回 `inconsistent`，Flutter 显示提示并保留原校准。这里不新增分段时间映射能力。
- 重复乐段返回 `ambiguous` 时不修改项目，也不将次优候选提升为自动成功。用户进入候选试听，选择候选并分别播放参考/目标后，才可显式采用；保存为 `confirmed`。
- 试听关闭共享播放器，复用手动校准的两路独立预览，始终只播放一路声音。候选切换会重新定位并清除试听确认状态。保存失败可重试，取消不修改校准；释放预览后才重新打开共享播放器。
- 旧 `auto_review` 项目不会被删除或重写，但显示“待复核”，提供重新匹配入口，不再标作普通自动成功。

## 回归入口

```text

cd mobile/app
```

新增 Rust 回归覆盖前段/中段/末段插入与删除、0.3%/0.5% 微小速率差、重复乐段和局部核验取消。Flutter 回归覆盖候选不自动保存、保留锚点、保存失败重试、跨项目候选失效、逐路试听/竞争操作、定位失败、两种小屏布局与两倍文字缩放、实际确认及预览释放顺序。

本修复未修改播放时钟、视频时间映射、渲染或导出管线。历史导出审计不算作修复后新导出；主机音频重放不等于手机原生解码或物理声画延迟测量。

## 本轮主机音频重放

使用冻结测试素材的 FFmpeg 解码 PCM，通过本轮构建的 Rust release C ABI 运行 31 项：7 项原矩阵、10 项小速率差、12 项剪辑插入、重复乐段与不同音乐各 1 项。无音轨检测属于原生适配器，本轮主机重放不计该项。

- 12 项中/末段 80–400 ms 插入在旧版中有 8 项误报 `matched`；修复后均为 `inconsistent` 或 `no_match`，不会自动写入项目。
- 约 18 秒真实音乐的 0.995 速率样例：最大端点映射误差从 46.460 ms 降至 4.856 ms；23 秒合成音乐的 1.003 样例从 37.000 ms 降至 3.421 ms。10 项速率样例均仍匹配，最大误差小于 35 ms。
- 原矩阵的 6 项有真值音乐匹配均保留，短片仍拒绝；重复乐段仍返回多个候选，不同音乐仍拒绝。

这些是两条已知音轨及其派生 PCM 的主机结果，不代表所有录音、长视频或手机声学输出均通过。

## PR #39 审计跟进（2026-11-19，macOS 主机）

针对审计复现的两项新增回归及一项片尾修复缺口，补充以下修复：

- 重复乐段不再直接返回尚未拟合的 `scale=1` 候选。对各原候选分别拟合并核验，保留至少 95% 的原共同区间；即使只剩一个有效候选，仍需用户复核，不提升为自动应用。短于六秒、无法进行速率拟合但多窗口稳定的重复乐段仍可复核。
- 弱相关不再直接等同于时间跳变。局部核验要求出现足够强、明显优于当前位置的其他时差证据，避免将短时录音噪声误判为剪辑。
- 首尾增加 200/300 ms 短窗口，并从两源方向核验，避免片尾插入被长窗口平均、片头删除被共同区间裁切掩盖。200 ms 窗口使用更严格的相关阈值。

新增五项可移植 Rust 回归，覆盖：30 秒重复乐段叠加 0.995/1.004 速率差、3.5 秒短重复乐段、一个候选失效后仍需确认、两路音源首/中/尾各两秒的附加噪声，以及靠近首尾的 80/400 ms 插入和 400 ms 删除。重复变速用例要求两个候选的首尾映射误差均小于 35 ms；20 秒音轨在 19.5 秒插入 400 ms 的审计样例不再自动应用。原始三条独立审计断言也已由失败转为通过，临时审计脚本不加入仓库。

## 再次审计修复（2026-11-19）

扩展审计发现 `4d306fb9` 仍存在三类问题：17 秒处插入一秒的样例超出局部时差搜索范围后被自动接受；部分重叠音轨的静音边界会触发伪冲突；变速多候选分支仍可绕过局部核验。本次分别修复：

- 保留附近时差扫描，并按全曲频谱峰索引提出较大时差候选，再对有限候选做细粒度相关核验。大时差和短边缘窗口还要求原始频谱峰对应优于当前位置，防止将短时噪声或相似长音的伪峰当成跳变，而不是恢复“弱相关直接失败”的规则。
- 核验窗口限制在双方实际有音乐的范围内，并避开外部静音与音乐之间一个 FFT 窗口的过渡帧。只调整核验探针，不改保存的映射、共同播放区间或拟合支持长度；内部静音插入仍被检查。
- 常速复核、变速复核以及全局变速搜索无结果时的单候选回退都必须通过核验。冲突候选被移除；原本需要复核的结果即使只剩一个有效候选，也不自动应用。

新增六项 Rust 测试，覆盖 801 ms–12 s 的首/中/末段插入和删除、三种音符密度与三个音乐种子的 27 个部分重叠组合、额外的首尾静音长度组合、0.8/1.25 变速重复乐段中的 80/400 ms 剪辑、仅一个变速候选有效时仍须确认、单常速候选回退核验，以及宽时差索引的取消检查。上轮噪声、微小速率差和亚秒首尾剪辑测试同时保留。再次审计的三条独立断言也已由失败转为通过，临时脚本不提交。

本轮重新通过：Rust 格式、严格 Clippy 和 125 项测试（含文档测试）；主机 release 库重建与 `tools/rust/audio_smoke.py` C ABI 重放/取消检查；Flutter 应用 286 项、domain 28 项及 `lib test test_driver` 源码分析；完整 Swift/原生 PCM/AVFoundation 合成导出主机回归。Swift 警告和真机验收限制同上，未将主机通过记作设备验收。
