## 四项交付

### 正式比较与共享播放

ComparisonSession 复用已验证的共同音频时钟、双 MediaCodec 和单 GL 合成，输出一个 Flutter SurfaceProducer 纹理。音频只播放老师轨；学生轨用于匹配时分析，不叠加播放。老师无音轨时允许手动比较，使用单一单调时钟。

原生 Choreographer 驱动调度；Dart 每 200ms 读取状态以更新控件，不负责两路定时。暂停状态不再重复触发页面与无障碍状态重建。后台暂停，返回前台保持暂停；屏幕旋转重新配置共享纹理并保留共同位置。

### 自动音乐对齐与候选试听

在手机本地使用 MediaExtractor / MediaCodec 解码音轨，经 Media3 Sonic 统一到 16kHz 单声道，再使用频谱峰值指纹产生候选、频谱与起音相关细化，并分别检查三个乐段的位置一致性。

偏移定义为「学生源时间 = 老师源时间 + offsetUs」。

算法只估计共同音乐的常量偏移，不根据人物动作提前或延后时间，也不做速度拉伸。现场录音的自动应用同时要求足够音乐证据、至少 8 秒支持、三段一致、最大局部偏差不超过 20ms 和明显的候选差距；高相似度直接音轨也须通过多段与歧义检查。重复乐段、变速或证据不足会显示候选或手动入口，不显示“置信百分比”。

真机暴露并修复了一个编译无法发现的问题：Media3 1.9.2 的 Sonic 无参 flush() 会抛异常。现使用 flush(AudioProcessor.StreamMetadata.DEFAULT)，并对本次两种实际采样率补了输出样本数与尾部排空回归。

### 手动兜底

「手动校准」填写同一歌词或鼓点在两段原片中的时间，支持秒、分:秒和六位小数；校验时间位于各自视频内，计算偏移、跳到共同事件并保存。原有人工信息是“老师 0 秒对应学生大约 2 秒”，本轮直接复用，没有再次要求确认。

真实设备输入 0 / 2 后，项目保存为手动 +2,000,000µs，两项源锚点也精确保存。取消选片不会清除原片引用或校准。候选试听会播放并在约 8 秒后暂停，可继续手动微调。

### 项目保存与恢复

系统 ACTION_OPEN_DOCUMENT 保留用户授权的 URI 读取权，不扫描相册、不复制或上传原片。项目通过 Android AtomicFile 存入 app 私有、排除备份的 noBackupFilesDir/comparison-projects。

保存字段包含名称、两段来源、音乐偏移及校准方式、手动锚点、共同进度与速度。播放进度每约 3 秒自动保存，后台、离开页面和显式保存会提交当前状态。写入串行化以防旧进度覆盖新校准；保存失败时阻止退出、切换或新建覆盖当前项目。系统突然结束进程时，尚未到自动保存时点的最近进度可能丢失。

当前 Debug 安装在项目库为空时，导入原先已经授权的 M0 原片引用和手动锚点，避免再次选片。这条迁移仅在 Debug 生效，Release 首次使用走正常系统选片。

## 适用范围与下一步

本轮覆盖当前 Android 手机和这组原片。自动匹配暂限十分钟内音轨；重复音乐、剪辑或速度不同仍可能需要候选试听和手动选择。匹配规则已通过上述反例和当前原片，尚未建立多舞曲、多录音环境的准确率基准。

长时真实素材、多机型、iOS 比较、双路导出和人物评分不在本轮验收结论内。后续优先围绕实际练舞补上 **A/B 分段循环、老师镜像和更方便的校准预听**，再扩展歌曲与设备覆盖；无需回到 M0 等待长原片后才继续产品工作。
